# Controller input investigation status

Status: historical report from repository issue discussion; not independently
reproduced in this audit.

Date recorded: 2026-09-14.

## Why this file exists

The repository issue about measuring multi-controller input points to a report
on a branch that is not present in this checkout. The issue comment is useful
lead evidence, but a comment and a missing branch are not a current regression
fixture.

## Reported observations

The issue discussion reports these observations:

- controller reads use eight-byte records at guest address 0x8011C640;
- the OSContPad mapping is identity by SI channel, with a six-byte stride;
- a setter path writes player records, and the menu writer is not the only
  writer;
- Controller Pak save interleaving was left open;
- the no-input state appeared to match across all eight ports;
- a channel-zero guard left channels one through three as an input gap in one
  path.

These are reported observations, not claims that this branch currently
implements or tests all of them. The named report file is absent from this
worktree, and the measurements were not rerun here.

## Required recovery

Before changing multiplayer input code, a human owner should recover or repeat
the measurement with:

1. the exact ROM identity and emulator version;
2. a capture of the controller read and write buffers;
3. channel-by-channel input for one through four players;
4. a Controller Pak transaction captured at the same time;
5. a checked-in fixture or focused test that can run without a copyrighted ROM
   when possible.

Until then, do not use this investigation as proof that a new input layout or
save interleave is correct.
